# Aktualisierung

Die Aktualisierung Ihrer Terminologie kann sich unterschiedlich gestalten.
Grundsätzlich sollte man sich beim Start eines Open-Source-Projektes darüber im Klaren sein, dass hier eine Ressource erstellt wird, die auch nach ihrer Erstellung verwendet werden soll und somit auch weiterhin Anfragen nach sich ziehen kann.
Zudem entwickeln sich Terminologien kontinuierlich weitere, insbesondere in dynamischen Kommunikationsbereichen wie der Forschung.
Die Terminologie sollte deswegen als Ressource idealereeise redundant verankert werden, um ein langfristiges Commitment sicherzustellen.
Wie dies genau erreicht werden kann, sollte vorab geklärt werden.
Eine rein institutionelle Zugehörigkeit macht nur dann Sinn, wenn die zugehörige Expertise dauerhaft verfügbar ist.
Wandert diese ab, ist eine personelle Zugehörigkeit eventuell sinnvoller.
Sinnvoll ist es, das Terminologieprojekt bereits bei seinem Start auf mehrere Beine zu stellen, zum Beispiel, indem es mit fachlichen Partnern als gemeinsame Ressource entwickelt wird.

Änderungen können punktuell erfolgen und kontinuierlich eingespielt werden. Hierzu könnten tagesaktuelle Releases erstellt werden.
Alternativ könnte man auch eine feste Überarbeitungsperiode in festgelegten Intervallen festlegen, in der dann alle angehäuften Issues abgearbeitet werden und im Anschluss ein größeres Release herausgegeben werden.

Da Anfragen auch von außerhalb der Erarbeiter- oder Herausgebergruppe an das Projekt herangetragen werden können, sollte auch geklärt sein, wie man darauf reagiert und ob und wie solche Anfragen bearbeitet werden sollen.
Wünschenswert wäre hier natürlich, dass das Projekt responsiv bleibt und Änderungsvorschläge angenommen, diskutiert oder ggf. auch begründet abgelehnt werden.
